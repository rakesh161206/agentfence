Legitimate tools are used for harmful ends. Least-privilege grants, path and destination scope, and rate and call budgets constrain the blast radius; A2, A3, and A6 exercise it.

Tool metadata, interfaces, or routing are tampered with. The prototype assumes trusted adapters and does not verify tool identity.

Agentic supply chain

Compromised models, plugins, or datasets. There is no AIBOM/SBOM, signature verification, or dependency attestation.

out of scope
ASI05
Unexpected code execution

Generated code runs with host privileges. The prototype has no code-execution tool and no sandbox-escape defense.

out of scope
ASI06
Memory and context poisoning

Retrieved content is labelled untrusted and tainted across later actions. Embedding and persistent-memory integrity are not checked.

partial
ASI07
Insecure inter-agent communication

Spoofed or modified messages between agents. The gateway is single-agent and does not authenticate agent-to-agent traffic.

out of scope
ASI08
Cascading failures

Per-task budgets and approval gates limit runaway work. There is no cross-agent circuit breaker or automatic rollback.

partial
ASI09
Human-agent trust exploitation

The approval preview is exact, the token is bound to the resolved action, and every decision is auditable. Human factors are not measured.

covered
ASI10
Rogue agents

Scope, expiry, budgets, and audit constrain drift. A kill switch and rollback are roadmap items; expiry is the current stop condition.

Best-practice alignment

done

Capability-scoped tools. Every task gets an explicit grant; unnamed tools are denied.

done

Action-bound credentials and budgets. The token commits to the grant; call and rate budgets travel with the task.

partial

Separate instructions from content. Provenance labels untrusted content, but prompts are not sanitized or restructured.

done

Human approval for high-impact actions. Sensitive calls pause on a hash-bound, single-use token with an exact preview.

AIBOM/SBOM and signatures. The gateway does not yet verify model, plugin, or tool artifacts.

roadmap

Kill switch and rollback. Task expiry exists; operator revocation and state rollback do not.

Where this leaves the idea

AgentFence is not a complete AI firewall. It is the enforcement plane that makes the other planes matter: a prompt filter can reduce the chance that a model is fooled, but only the action plane can refuse the resulting tool call.

The evaluation is deliberately scoped to that plane. The next layer of work is to connect input and output inspection to the same decision context, add task revocation and rollback, and attach an AIBOM so the gateway can verify what it is authorizing.

What AgentFence does not claim

The boundary of the prototype, stated plainly

scope
Not a model safety filter.

It does not moderate tone, toxicity, or hallucination, and it does not replace the model's own safety training.

Not a discovery or posture platform.

It does not inventory agents, map cloud exposure, or govern vendors. It assumes the agent and its tools are already known.

Not a training-data defense.

It labels and contains untrusted content at runtime. It does not detect poisoning in a training corpus or an embedding store.

About the project

What AgentFence is

A research prototype that checks what an AI agent is about to do, before it does it. The tests are scripted and simulated — they measure the enforcement layer, not how easily a particular model can be fooled.

Two layers of checking

Hard rules. Permissions, allowed files and destinations, sensitive-data rules, and rate limits. If a hard rule fails, the action is blocked.

Risk signals. Prompt-injection score, data sensitivity, unusual behavior, and destination reputation. These can ask a person to look, but they can never override a block.

The receipt. An approval is tied to the exact action. The decision log is a hash chain, so any change is detectable.

What this prototype is not

The tools are simulated. There is no real email, HTTP, or database access. The scenario traces are deterministic, so the numbers measure the policy engine rather than a particular model's willingness to follow an injection.

One attack still gets through: a hand-written paraphrase that hides the secret in ordinary prose. That limitation is reported in the paper and reproduced in the scenario lab.
